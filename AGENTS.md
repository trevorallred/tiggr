## Layout

pnpm workspace (`pnpm-workspace.yaml`) with each unit of code under `packages/*` — no flat
single-package layout, so a new package (e.g. a future AI test-runner) is just a new directory
under `packages/`, not a restructure.

- `packages/engine/` — the deterministic, dependency-aware Tiggr engine (see its `README.md`
  for the public API; dependency compilation lives in `packages/engine/src/definitions.ts` and the
  teardown/polling loop in `packages/engine/src/scheduler.ts`). Deliberately has **zero** dependency
  on any internal proprietary package: the handful of utilities it still uses (`Logger` and `messageFromError`) are
  reimplemented locally under `packages/engine/src/util/`, trimmed to only what Tiggr actually
  needs (e.g. no AWS Lambda JSON log formatting). Keep the engine standalone. Its `build/` output
  is tracked so it works as a git dependency; update it with the source changes.
- `packages/cli/` — the JSON-first `tiggr run` binary. It discovers a `tiggr.config.mjs` or
  `tiggr.config.js` suite in the caller's current directory. Its `build/` output is tracked so it
  works as a git dependency; update it with the source changes.
- `sample-app/` — the private HTTP dogfood target and suite. `pnpm --filter @tiggr/sample-app
  dogfood` boots it on an ephemeral port and verifies the built CLI's complete JSON run artifact.

The root is a private workspace container. `packages/engine/` is the sole npm publish target under
the `tiggr` name; its package manifest is authoritative for publish metadata and tarball contents.

## Build & test

Root `pnpm run build` / `pnpm run test` fan out to every workspace package (`pnpm -r run ...`),
while root `pnpm run lint` covers the full workspace through `.oxlintrc.json`. CI
(`.github/workflows/ci.yml`) runs all three on every PR via a pinned `pnpm/action-setup` version
matching the `packageManager` field in the root `package.json` — keep those two in sync, since a
pnpm-lockfile generated by one major version can fail `--frozen-lockfile` under another.
